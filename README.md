# Cabinet Material Calculator

Node.js + Express material and labor calculator with Wix member sign-in, paid feature access, and per-member saved projects and setup.

## Free and paid features

- Free: core calculations and print/export.
- Paid: saved projects, cabinetry standards, materials, and labor setup.
- Shop Overhead estimates a productive man-hour rate from a 52-week schedule, production employee wages, expenses, holidays, and efficiency. Holiday pay is optional. The estimate is applied to labor setup only when the user chooses it. Monthly expenses are annualized; set the payroll tax burden as a percent of wages, and enter benefits and additional leave costs as expenses, without duplicating production wages. Account for time off in efficiency.
- Install Set Up estimates fuel per job. The shop ZIP (Install Set Up) and job site ZIP (Calculator) are looked up in the bundled `zip-data.json` (US ZIP centroids, served by `/api/zip/:zip`). The straight-line haversine distance is multiplied by a road factor, then by round trips (a flat count plus one per N lineal feet, with separate counts when install is off), MPG and fuel price. Fuel cost is added to the grand total.
- New jobs start with the "Default Paint Grade Frameless" standard. Paid members can customize and rename their personal Face Frame and Frameless defaults.
- The server verifies active Wix Pricing Plan orders against `WIX_PAID_PLAN_IDS` for every protected write. A plan value sent by browser code is never treated as proof of payment.

## Render configuration

Deploy with the Render Blueprint in `render.yaml`. It creates the web service and PostgreSQL database. Configure these service environment variables:

- `MATERIAL_LABOR_BRIDGE_SECRET`: long random shared secret stored in Render and Wix Secrets Manager only.
- `WIX_CLIENT_ID` and `WIX_CLIENT_SECRET`: Wix app credentials used for server-side plan verification.
- `WIX_SITE_ID`: Wix site ID for Pricing Plans API requests.
- `WIX_PAID_PLAN_IDS`: comma-separated IDs of the paid plan(s) that unlock app features.
- `WIX_UPGRADE_URL`: Wix checkout or membership URL shown by the upgrade buttons.

- `ADMIN_MEMBER_IDS` (optional): comma-separated Wix member IDs allowed to edit the shared default catalog. Admins get an "Editing shared defaults" checkbox on the Material Set Up tab. Everyone without their own saved setup (all free users, and paid members until their first edit) starts from this list.

- `ADMIN_EMAILS` (optional): comma-separated member emails treated as admins, same as `ADMIN_MEMBER_IDS`.

`SESSION_SECRET` is generated by Render. `DATABASE_URL` is wired to the Render Postgres database. Keep `config.js`'s `wixParentOrigins` aligned with the published Wix site origin.

## Wix member bridge

In Wix Secrets Manager, create `MATERIAL_LABOR_BRIDGE_SECRET` with the same value configured in Render. Add the following as `backend/materialLaborBridge.web.js`, replacing the Render URL with the deployed service URL:

```js
import { currentMember } from "wix-members-backend";
import { Permissions, webMethod } from "wix-web-module";
import { getSecret } from "wix-secrets-backend";
import { fetch } from "wix-fetch";

const RENDER_URL = "https://your-material-labor-service.onrender.com";

export const getMaterialLaborSession = webMethod(Permissions.SiteMember, async () => {
  const member = await currentMember.getMember({ fieldsets: ["FULL"] });
  if (!member) throw new Error("Sign in to your Wix member account.");

  const profile = member.profile || {};
  const contact = member.contactDetails || {};
  const externalMemberId = member._id || member.id || "";
  const email = member.loginEmail || member.email || profile.email || "";
  const name = profile.nickname || profile.displayName
    || [contact.firstName, contact.lastName].filter(Boolean).join(" ");
  if (!externalMemberId) throw new Error("Wix did not return the member ID.");

  const bridgeSecret = await getSecret("MATERIAL_LABOR_BRIDGE_SECRET");
  const response = await fetch(`${RENDER_URL}/api/auth/wix/bridge`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "x-wix-bridge-secret": bridgeSecret
    },
    body: JSON.stringify({ externalMemberId, email, name })
  });
  if (!response.ok) throw new Error("Could not establish the app session.");
  return response.json();
});
```

In the Wix page code containing the app's HTML component (ID `html1`), pass the short-lived session token to the iframe:

```js
import { getMaterialLaborSession } from "backend/materialLaborBridge.web";

let sending = false;

$w.onReady(() => {
  const sendSession = async () => {
    if (sending) return;
    sending = true;
    try {
      const session = await getMaterialLaborSession();
      $w("#html1").postMessage({
        type: "wix-member",
        name: session.user.name || "",
        userId: session.user.id,
        sessionToken: session.sessionToken
      });
    } catch (_error) {
      $w("#html1").postMessage({ type: "wix-member-logout" });
    } finally {
      sending = false;
    }
  };

  $w("#html1").onMessage((event) => {
    if (event.data && event.data.type === "cutlister-ready") sendSession();
  });
  sendSession();
  setInterval(sendSession, 15 * 60 * 1000);
});
```

The browser's message is used only to establish identity and display the welcome name. The API independently checks Wix plan orders before allowing saves or setup changes.

## Local development

```bash
npm install
npm start
npm test
```

Without `DATABASE_URL`, the server uses a local JSON store. To exercise paid features, configure the Wix credentials and bridge secrets and load the app through the Wix member integration.
